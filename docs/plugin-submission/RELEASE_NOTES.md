# DevMesh v1.3.0

DevMesh v1.3 adds **Design-to-Code Studio**, an explicit screenshot/mockup/Figma/export/visual-reference implementation specialization on top of Website Product Builder, full-stack engineering, Mission Control, Agency Operations, Website Operations, WordPress Real Estate, and **Real Estate IDX / MLS**.

New design-to-code capabilities include:
- `design-to-code-studio` for reference intake through implementation, visual verification, bounded repair, QA, and production delivery
- `visual-reference-analyzer` for page/layout/component/asset analysis with `OBSERVED`, `INFERRED`, and `UNKNOWN` evidence labels
- `design-token-extractor` for coherent semantic typography/color/spacing/layout/control tokens without false precision
- `responsive-layout-inference` for deliberate desktop/tablet/mobile behavior when not every viewport is supplied
- `visual-fidelity-judge` for authoritative-reference vs rendered-implementation comparison without fabricated fidelity scores

The Design-to-Code Studio routes:
`reference intake → visual reference analysis → token extraction → responsive inference → sitemap/component architecture when needed → implementation/full-stack only as required → Browser QA → visual fidelity comparison → maximum three visual repair rounds → accessibility/security/performance QA → DevMesh Judge → deployment when authorized`.

Static pixels are not treated as a complete product specification. Hidden interactions, backend/API behavior, auth, data models, animation timing, routing, and unseen responsive behavior remain inferred or unknown unless supported by evidence. Visual fidelity remains `BLOCKED` or `NOT RUN` without a real rendered comparison.

The v1.2 Website Product Builder remains available for greenfield websites from requirements/product contract through design system, sitemap, UI component architecture, frontend, conditional backend/API/database, SEO, QA, and deployment.

The Agency Operations Control Center remains available for multi-client fleets, scheduled health monitoring, domain/SSL expiry, staged WordPress updates, change/visual history, plugin vulnerability maintenance, renewal tracking, tickets/SLAs, CRM/lead/MLS health, privacy/accessibility/content QA, and client onboarding/offboarding.

The Website Operations Specialist remains available for hosting/DNS/SSL, WordPress migration, restore drills, technical/real-estate SEO, Core Web Vitals, analytics, email deliverability, links/redirects, WP-Cron, RESO schema/provider inspection, emergency recovery, and client monthly reporting.

The WordPress Real Estate Specialist remains available for Site Health, plugin/theme conflicts, safe updates, WP-CLI, REST, IDX provider detection, WordPress↔MLS bridging, property search QA, listing freshness, IDX/VOW monitoring, performance/security, lead delivery and handover.

The **Real Estate IDX / MLS** specialization remains available through `real-estate-idx-mls`, `reso-web-api`, `listing-sync-search`, and `idx-compliance-review`. **RESO Web API** support remains evidence-based and the actual MLS/provider license/local rules remain authoritative for data access and display rights.

DevMesh v1.3 contains **111 composable skills**. The ChatGPT adapter reports unavailable private design-source access, writable workspace/runtime, browser, hosting, database, Search Console, analytics, CRM/email, MLS/provider, CI and production evidence as `BLOCKED` or `NOT RUN` rather than fabricating success.
