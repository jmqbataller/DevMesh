# DevMesh v1.0 — Website Operations Specialist

DevMesh v1.0 extends the WordPress Real Estate stack into ongoing client-site operations.

## Client Site Autopilot

Use:

```text
DevMesh Website Specialist:
Take over this client website.
Audit operations end-to-end, fix safe issues, verify affected journeys, and prepare a client report.
```

Typical flow:

```text
inventory
→ hosting / DNS / SSL
→ WordPress health
→ backups / restore readiness
→ plugin/theme risk
→ safe updates when authorized
→ security
→ performance / Core Web Vitals
→ SEO / Search Console
→ analytics / conversions
→ forms / email delivery
→ broken links / redirects
→ IDX / MLS / RESO when present
→ WP-Cron reliability
→ browser / lead QA
→ monthly client report
```

## New v1.0 skills

- `website-operations-specialist` — Client Site Autopilot/orchestrator
- `hosting-dns-ssl-doctor` — nameservers, DNS, TLS, HTTPS, redirects, CDN/proxy and origin diagnosis
- `wordpress-migration-specialist` — hosting/domain/staging migrations with rollback and Browser QA
- `backup-restore-drill` — backup completeness plus safe restore verification
- `seo-search-console-specialist` — technical SEO, crawling/indexing and Search Console evidence
- `real-estate-seo-specialist` — IDX/listing/community URL architecture and duplicate/thin-page controls
- `core-web-vitals-diagnoser` — measured LCP/INP/CLS root-cause analysis
- `analytics-conversion-qa` — conversion events and downstream analytics verification
- `email-deliverability-doctor` — SMTP/SPF/DKIM/DMARC/form/CRM delivery-chain diagnosis
- `broken-link-redirect-manager` — 404/link integrity and safe redirect mapping
- `plugin-theme-risk-intelligence` — component criticality/support/compatibility/removal risk
- `wp-cron-reliability-doctor` — missed/duplicate/stuck scheduled jobs and scheduler architecture
- `reso-schema-drift-detector` — RESO/OData `$metadata`, resource, field and lookup drift
- `reso-provider-capability-inspector` — provider transport/capability evidence vs licensed permission
- `client-monthly-website-report` — evidence-based client-facing maintenance report
- `website-emergency-recovery` — outage triage from DNS/SSL through hosting/runtime/WordPress and verified recovery

## Evidence boundaries

DevMesh never treats these as equivalent:

- public DNS observation vs DNS-dashboard access
- backup existence vs successful restore
- browser analytics event vs downstream reporting
- form success message vs inbox/CRM delivery
- source-level SEO review vs Search Console/indexing evidence
- page HTTP 200 vs full website recovery
- RESO technical capability vs MLS licensed permission

Missing access is reported as `BLOCKED` or `NOT RUN`.

## Emergency example

```text
DevMesh Emergency:
The WordPress website is down.
Diagnose DNS, SSL, CDN, hosting, PHP, database, WordPress, plugins, theme, cache and recent changes.
Stabilize safely and prove recovery on the affected journeys.
```

## Monthly report example

```text
Use DevMesh.
Prepare this month's client website report using only verified evidence.
Include maintenance, backups, security, performance, SEO, leads, IDX/MLS freshness, incidents, completed work, blockers and next actions.
```

Never include passwords, tokens, API keys, MLS credentials, private customer data, or invented metrics in client reports.
